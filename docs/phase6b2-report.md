## 2. 决策：Action Loop 落位在既有页，而不是新建页面

`product-scope.md §7` 把 Action Loop 描述为「**F4 重构为** Gap & Action Plan + Retest」——
即它是 `f4-report.html` 的重构，不是新增第 5 个工作区。本阶段照此执行，理由是能力边界而非省事：

| 若新建页面 | 若重构 F4（本阶段选择） |
| --- | --- |
| 雷达图与 C0 证据快照要复制一份，或让新页面反向依赖 F4 | 雷达图 / C0 快照 / 缺口清单本来就在同一页，复测前后能同屏对照 |
| 导航会变成 5 项，与 ≤4 的产品门禁直接冲突 | 保持 4 项 —— 少一个格子换来的是"一个工作区一件事" |
| 用户要先看缺口的来源（能力报告）才能理解行动，多一次跳转 | 「缺口 → 行动 → 复测」是一条连续的视线 |

**限定语留在界面上（有判据锁死）**：行动「已完成」不等于缺口「已解决」；没有可验证成果物的
缺口不会开单。这两句不是文案润色 —— 前者防止把"打了个卡"读成"问题没了"，后者防止把
"系统没给我开单"读成"我没有这个缺口"。

## 3. 去 F 代号：判定范围包含 URL

DoD #2 说的是"用户可见面不出现内部代号"。**URL 是用户可见面** —— 分享一个链接、
在看板里贴一个地址、在浏览器标签上看一眼，看到的都是文件名。所以这次连文件名一起换：

| 旧 | 新 |
| --- | --- |
| `pages/f1-resume.html` | `pages/resume-evidence.html` |
| `pages/f3-interview.html` | `pages/interview-practice.html` |
| `pages/f4-report.html` | `pages/action-loop.html` |
| `pages/f5-apply.html` | `pages/job-apply.html` |
| `js/f3-interview.js` | `js/interview-practice.js` |
| `js/f5-apply.js` | `js/job-apply.js` |

配套动作：

- 两棵发布树同时改名，改后**逐字节一致**（镜像不变量未被破坏，§5 第 9 步）；
- 页面 `data-page` 由 `f1/f3/f4/f5` 改为 `resume / interview / action / apply`；
- **投递页退出导航**：它是目标岗位的子页，不是一级工作区。由目标岗位页的出口区链入；
- 新增判据：发布树里不得再有带 F 代号的**路径**或**可见文本**（`.md` 是历史记录，不在范围内）。

**改名最容易漏的一类残留**：测试里以**转义正则字面量**写死的旧文件名，例如
`/f3-interview\.js/`。按字面串做替换的扫描**扫不到**它们（源码里是 `f3-interview\.js`），
结果是 4 个测试在改名后失败 —— 这是修复而非噪音，记在这里以免下次重踩。

## 4. 三个判据缺陷（本轮修掉的，都是"判据的观察面与实际面不重合"）

### 4.1 死代码不会让测试变红，只会让控制台每次都报错

`f4-report.html` 里内联着一段「F1–F3 完成进度追踪器」，引用 6 个**早已不存在**的 DOM id
（`progressSummary` / `progressBarFill` / `connector1` / `connector2` / `progress-step` /
`progress-tracker`）。它每次加载都抛 `TypeError`，但**没有任何测试会因此失败** ——
因为没有任何测试在看"页面声明的 id"与"脚本引用的 id"是否对得上。而且它自身带着 F 代号，
正好落在本轮要清理的范围内。

修法有两层：删掉它，并**新增通用判据** —— 页面的内联脚本不得 `getElementById` 一个
该页没有声明的 id。这条判据对后续所有页面生效，不只是这一页。

### 4.2 路径扫描排除了 `.md`，于是文档漂移不在任何判据的观察面内

改名之后，`docs/architecture.md §2` 与 `docs/product-scope.md §1` 的页面表格仍指着旧文件名。
**没有任何测试会失败**：现有路径扫描（`test_phase6b2_contract.js`）只覆盖发布树，
且显式排除 `.md`（因为 `.md` 里大量历史报告本来就该保留旧名）。

问题在于**活文档不只是历史**。`architecture.md §2` 的表格是"当前有哪些页面"，
真人会照着它去找文件 —— 它烂掉和路由烂掉是同一类事故，只是没有机器在看。

修法：新增 `scripts/live-doc-path-check.py`（门禁第 10 步），对活文档
（`architecture.md` / `dependency-map.md` / `product-scope.md` / 两棵 `README.md`）
里的每个 `pages/*.html` 引用要求：**要么指向真实存在的文件，要么同一行（或本节标题）
带明确的历史措辞**（已删除 / 已下线 / 已修 / 审计 / 完成记录）。

文档本身按新口径修正：4 个改名页给出「旧名 → 新名」对照（读者真正要的就是这张表）、
两个已删除页面划掉并注明何时删的、两个审计快照表格的标题写明是快照。

### 4.3 判据的"历史语境"窗口太宽 → 遮蔽（变异测试抓到）

第一版门禁把"历史语境"的判定写成"上下 ±10 行内出现历史措辞即放行"。变异测试立刻打脸：

| 注入 | 期望 | 实际（±10 行版） |
| --- | --- | --- |
| §2 现况表格里塞 `pages/action-loop-NOPE.html` | 失败 | **通过** —— 8 行之外的注记把它开脱了 |
| 把改名后的页写回旧名 `f1-resume.html` | 失败 | **通过** —— 同上 |

**遮蔽方向搞反了就是放过漂移。** 收紧到"同一行或本节标题"之后，同一个注入 exit 1。
这里还有一处连锁发现：**我为了说明"这节是快照"而把 §2 标题改成「用户页面（审计时的 8 个
HTML）」，这一步本身就让整节表格重新落进遮蔽区** —— 于是标题改为不带任何历史措辞的
「用户页面（快照：8 个 HTML）」，历史结论交给紧随其后的注记段落和**每一行自己的标记**。
收紧后三次注入的结论：无标记死链 exit 1、旧名回写 exit 1、带「已删除」标记的死链 exit 0。

**同一类错误的三个变体**（6a / 6b-1 / 6b-2）值得并排记：

| 阶段 | 缺陷 | 观察面与实际面哪里不重合 |
| --- | --- | --- |
| 6a | `cmd \| tail -5; echo $?` | `$?` 取的是 `tail` 的退出码，永远为 0 |
| 6b-1 | `git diff --check` | 只看**未暂存**差异，而流程恒为"先 `git add -A` 再跑门禁" → 空转 |
| 6b-2 | `±10 行` 的历史语境窗口 | 窗口比"这一行到底在说什么"宽，遮蔽了漂移 |
