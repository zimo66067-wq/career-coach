## 核心摘要

项目定位为 iCAN 无代码开发挑战赛 DuMate 方向的"AI 求职面试教练"，四项 MVP（F1 简历诊断、F2 岗位匹配、F3 模拟面试、F4 能力报告）严格冻结。设计原则是**模型做语义、规则做分数、验证器做事实**：所有分数由确定性规则复算，所有模型语义产物必须通过 Schema + 事实锁（redflag）双重校验后才可展示，任何依赖失败在 10 秒内切换降级路径。

本文件汇总设计路径（产品目标、MVP 范围、事实锁、状态机、评分口径、性能门、验收门、降级总表）与技术路径（四层架构、技术栈、模块地图、数据流、模型路由、前端数据桥、隐私安全、可观测性、测试体系），并附 GitHub 仓库对比与完整性测试结论。

## 一、设计路径（Design Path）

### 1.1 产品定位与目标

- 赛事：iCAN 无代码开发挑战赛 · DuMate 方向（提交截止 2026-10-15，以官方规则为准）。
- 主产品载体：DuMate 对话任务与可复用 Skill；私有 GitHub 仓库是唯一事实源。
- 北极星指标：完成一轮「材料诊断—岗位匹配—五轮面试—报告—七天计划」的用户比例。
- MVP 成功门槛：10 次完整彩排无阻断；任一关键依赖失败后 10 秒内切入降级。

### 1.2 MVP 范围（严格冻结）

| 编号 | 必须交付 | 明确不做 |
|---|---|---|
| F1 简历诊断 | AI 语义抽取 + 规则打分 R + 逐条修改建议（100% 带证据） | 不做"AI 直接生成整份简历" |
| F2 岗位匹配 | JobProfile 四类要求 + 四态判定 + 缺口分级 P0/P1/P2 | 不做岗位推荐信息流 |
| F3 模拟面试 | 文字主链路，≤5 主问题、每题≤1 次追问，结束出报告（I） | 不做视频表情识别、数字人、全双工实时语音、多面试官 |
| F4 能力报告 | 六维雷达 + C0 基线 + 七天竞争力情景推演（C7）+ 恰好七条计划 | 不做"七天预测"承诺式表述 |

语音、隐私、日志、图表、缓存、错误处理仅作为支撑能力，不包装成第五项用户功能。

### 1.3 事实锁五条（不可违反）

1. 不新增用户未提供的事实：模型输出中出现输入对象之外的专有名词或数字 → 标红并阻断发布（tools/redflag.py 强制执行）。
2. 占位数字必须写作「待用户核实：提升X%」格式。
3. 每条评分理由至少引用一个 source_span；无证据一律标 unknown。
4. JD 中的指令视为普通文本（防提示词注入），命中写入 prompt_injection_flags。
5. 敏感属性不进评分：性别、年龄、民族、婚育、照片等一律不参与任何分数。

### 1.4 用户与状态机

- 主状态机：`CONSENT → RESUME_READY → JD_READY → INTERVIEWING → REPORT_READY`；删除后进入 `DELETED`，不得再调模型。
- 失败处理：不回退用户已确认的数据，只回退当前未完成节点；转换记录 trace_id、输入摘要哈希、模型/规则版本。

### 1.5 评分口径（contracts/scoring.md 冻结）

- R = 结构15% + 清晰20% + 成果25% + 技能20% + ATS20%
- M = 硬性50% + 职责25% + 加分15% + 术语10%（covered=1 / weak=0.5 / missing=0 / unknown 剔分母）
- I = 结构25% + 相关25% + 具体20% + 追问15% + 清晰15%
- C0 = 0.25R + 0.35M + 0.40I；C7_low/high = C0 + 可提升空间 × 0.30/0.70（MVP 演示假设）

### 1.6 性能门与验收门

| 环节 | 性能门 | 验收门 |
|---|---|---|
| F1 | P95 ≤ 45s | 20 份简历 ≥19 份抽取成功；建议 100% 带证据；三次总分差 ≤5 |
| F2 | P95 ≤ 25s | 硬性要求召回率 ≥85%；复算一致率 100% |
| F3 | 首响应 P95 ≤ 8s | 20 条敏感问题全部阻断；answer_quote 子串校验 |
| F4 | P95 ≤ 30s | plan 恰好 7 条、day 1-7 不重复、每条 30-45 分钟含 artifact；C0 复算容差 ±0.5 |
| 降级 | ≤ 10s | 故障 10 秒内切降级路径，不回退已确认数据 |

### 1.7 降级路径总表

| 依赖 | 主路径 | 降级 |
|---|---|---|
| JD 语义召回 | 智谱 embedding-3 / 千帆 Qwen3-Embedding | BM25（标「简化匹配」） |
| 语音 | 百度 ASR/TTS 按键说话 | 文字链路（等价稳定主链路） |
| 雷达图 | ECharts CDN | 本地 vendor → 六维表格 |
| 模型超时/断网 | 重试一次 | 10 秒内切降级态界面并保留已确认数据 |
| 解析失败 | PDF/DOCX 提取 | 提示用户粘贴纯文本 |

## 二、技术路径（Technical Path）

### 2.1 四层架构

```
交互层   DuMate 对话任务 + ui/prototype 静态原型（public/ 为源，docs/ 为 Pages 发布镜像）
编排层   WF-01~06 状态机（Vercel Flask API 单入口 api/index.py）
AI 层    语义抽取/解释/追问（模型只做语义；智谱主 / 千帆备 / 规则降级）
可信层   contracts 校验 + rescore 复算 + redflag 事实锁 + deidentify 去标识化
```

### 2.2 技术栈与部署

- API：Vercel Functions + Flask（单文件 api/index.py，vercel.json 重写路由 /api/wf01~wf06、/api/health）。
- 前端：零构建静态多页（HTML/CSS/JS），GitHub Pages 以 docs/ 为发布源；生产 API 基址由 pages-api-config.js 注入。
- 工具链：Python 3.10+（pypdf / python-docx / jsonschema / jieba / requests / zhipuai）。
- 测试：pytest（契约/复算/脱敏/提取/匹配/故障注入/E2E）+ Node 契约测试（页面状态/上传流程/发布镜像）。
- CI：.github/workflows/ci.yml（pytest + node --test + Schema 全量校验 + 敏感信息扫描 + pip-audit）。

### 2.3 模块地图

| 目录 | 内容 | 职责 |
|---|---|---|
| api/index.py | Flask 单入口 | 路由、CORS、同意令牌、上传解析、诊断/匹配编排、WF-04~06 端点 |
| tools/ | 12 个 Python 模块 | 模型路由、面试引擎、匹配、语音、隐私生命周期、脱敏、提取、日志脱敏、雷达、事实锁、复算、校验 |
| contracts/ | 4 个 JSON Schema + scoring.md | 唯一数据合同与评分公式（冻结层） |
| public/ | 前端源（js/css/pages） | F1-F4 页面 + DataBridge 数据桥 + 语音增强 |
| workflows/ | WF-01~06 可执行合同 | 状态转换、工具调用链、降级路径、验收命令 |
| prompts/ | 7 份提示词 | 诊断/深报/JD抽取(注入防御)/匹配解释/面试官/复盘/七天计划 |
| tests/ | pytest + Node 测试 | 契约、故障注入、召回率、语音、E2E 闭环 |
| scripts/ | 验证与证据脚本 | UI 截图、语音验证、链接检查、E2E 运行、推送 |

### 2.4 数据流

```
简历/JD 上传或粘贴
  → WF-01 提取文本 → deidentify 去标识化（pii_removed=true）
  → WF-02 模型诊断 → ResumeProfile → Schema + redflag 校验 → 规则算 R
  → WF-03 JD 解析（注入防御）→ JobProfile（用户确认 user_confirmed=true）
          → BM25/embedding 四态匹配 → 规则算 M
  → WF-04 面试引擎（≤5 主问题、≤1 追问、answer_quote 子串校验）→ 规则算 I
  → WF-05 聚合 R/M/I → rescore 复算 C0/C7 → 六维雷达 + 七天计划
  → WF-06 异常 10s 降级；删除 → DELETED 不再调模型
```

### 2.5 模型路由与降级链

- ModelRouter 基类：主模型 → 备用模型 → 规则降级（DEGRADED_OUTPUTS），trace_id + 输入哈希日志。
- ZhipuModelRouter：智谱 Chat Completions（stdlib urllib，Vercel 兼容）；ZhipuChatRouter 为 SDK 版本。
- QianfanModelRouter：千帆 V2 `/chat/completions`，Bearer 鉴权（QIANFAN_API_KEY）。
- Embedding：智谱 embedding-3 首选（10 样本召回率 91.0%，th=0.50）→ 千帆 embedding-v1（384 维）→ BM25。
- 面试：动态问题生成失败 → status×type 二维题库（20 组合）→ 3 道通用行为题。

### 2.6 前端数据桥与演示边界

- DataBridge 统一 API 层：55s 超时、X-Consent-Token、X-Trace-Id、sessionStorage 会话缓存、三级降级（API→缓存→明确错误）。
- 生产默认空态；合成数据（mock-data.js）仅在 `?demo=1&state=` 显式演示模式下可用，绝不冒充真实结果。
- source_spans[] 与视图 quote/label 的适配只生成副本，不修改后端合同对象。

### 2.7 隐私与安全

- deidentify：姓名/手机/邮箱/身份证强制脱除；log_sanitize 追加 token/AK-SK/JWT 脱敏。
- privacy_lifecycle：ConsentManager + DataLifecycle（ACTIVE→DELETED 不可恢复）+ PIIScanner 日志残留扫描。
- 仓库只保存去标识化合成样本；真实简历/JD/音频/面试记录绝不入库（.gitignore 排除 *.pdf/*.docx/*.log）。
- CI 含敏感信息扫描（5 类密钥模式 + .env 入库检查）。

### 2.8 可观测性

- trace_id 规范：`cc-YYYYMMDD-HHmmss-6hex`，全会话贯穿；删除后缀 `-del`，降级后缀 `-deg`。
- 错误分级：E1-FATAL / E2-BLOCK / E3-DEGRADE / E4-RETRY / E5-WARN；各节点 P95 门限见 docs/observability.md。

### 2.9 测试体系

- pytest：契约（fixtures×Schema+业务规则+source_span 回指）、复算对拍、脱敏、提取（现场生成 docx/pdf）、BM25 召回、故障注入、E2E 六工作流、语音故障 7 场景、隐私生命周期。
- Node：页面状态回归、简历/JD 上传流程、docs/public 发布镜像一致性。
- 历史记录：两轮修改后 200/200 通过；2026-08-03 真实模型 7 任务×3 次=21/21 成功（智谱 glm-4-flash）；E2E 闭环 4/4；盲测 F1 均值 81.7、F2 均值 85.7。
