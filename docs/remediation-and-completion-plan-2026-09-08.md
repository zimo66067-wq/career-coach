# 职跃 AI 阻断修复与完整交付计划（2026-09-08）

## 1. 目标与边界

本计划以 GitHub `main` 的 `792fd571` 为基线，目标是把项目从“页面可访问的原型”推进到“核心闭环可用、安全措施上线、可执行正式验收”的状态。

本轮执行遵守以下边界：

- 先关闭阻断问题，再处理增强项和交付项。
- 所有功能必须经过浏览器、API、数据库和返回渲染四层验证。
- 先部署 Preview，验证通过后才允许合并 `main` 和发布 Production。
- 测试或验收产生的数据必须带唯一审计标识，并在验收后删除。
- 不把“代码存在”“单元测试通过”写成“线上功能完成”。
- G8 真实用户验证必须由真实参与者完成，不伪造用户、时长和反馈。

## 3. 执行优先级

### 阶段 A：关闭全部 P0 阻断

#### A1. 修复 Vercel F2 专业 API 路由

实施：

- 将专业树、搜索、详情、意图和专业匹匹配统一接入主 Flask API 入口。
- 不再依赖会被 Vercel 后端框架重写行为影响的第二 Python Function。
- 保留既有 `/api/f2/*` 公共契约，前端无需更换 URL。
- 为路由增加 API 合同测试和 Vercel 配置静态测试。

完成标准：

- `/api/f2/health` 返回 200，专业数为 845、画像数为 30。
- `/api/f2/majors/tree` 返回 200 且目录非空。
- 搜索、专业详情、意图识别和两种匹配模式均通过测试。

#### A2. 贯通 F1-F5 单一会话

实施：

- 建立一个明确的客户端会话读取/写入入口。
- F2 解析与匹配、F3 启动/回答/结束、F4 汇总、F5 改写与投递全部传递同一个 `session_id`。
- 禁止 F3 无条件生成新会话并覆盖已有训练会话。
- 后端对请求体、存储记录和所有者进行一致性校验。
- 增加“前端真实调用形态”的端到端契约测试，避免仅后端直调通过。

完成标准：

- 同一浏览器会话依次完成 F1→F2→F3→F4→F5。
- F4 能正确读取该会话的 R/M/I，不再返回 `insufficient_evidence`。
- 跨用户或伪造 `session_id` 只能得到 404/403，不能读取、修改或删除数据。

#### A3. 修复真实模型调用

实施：

- 简历改写统一使用 `ModelRouter.call(task_type, user_input, context)`。
- 为求职信新增冻结任务类型、提示词、参数配置和规则降级。
- 对模型返回内容做长度、事实引用和空输出校验。
- 测试主模型成功、备用模型、超时、非 JSON 和规则降级路径。

完成标准：

- 配置模型时，简历改写与求职信返回 `basis=model`。
- 未配置或模型失败时，明确标记 `basis=rule`，页面不能伪装为模型结果。

### 阶段 B：页面与基础框架完善

实施：

- 统一首页、F1-F5、知识库的导航、会话状态和错误状态。
- 所有表单补充输入约束、加载态、失败态、重试入口和键盘可访问性。
- 修复小屏导航、长文本溢出、焦点管理和对比度问题。
- 保持 `public/` 与 `docs/` 发布镜像一致，并由 CI 强制检查。
- 将 API 路由集中到单一入口，拆分业务服务，避免 Vercel rewrite 与 Flask 路由互相覆盖。
- 增加结构化日志、请求 ID、健康检查明细和不包含 PII 的故障上下文。

完成标准：

- 375px、768px、桌面三档页面无横向溢出。
- 页面不存在未处理的控制台异常或失败网络请求。
- 错误、降级和空状态均能被用户理解并恢复操作。

### 阶段 D：线上完整业务闭环

实施：

- 在 Preview 使用生产同构环境变量验证 PostgreSQL、模型和 CORS。
- 使用合成材料执行浏览器 F1→F5 全流程。
- 验证注册/登录、刷新恢复、重新登录、历史记录、主动删除。
- 验证模型超时、数据库失败、F2 专业数据缺失时的用户可见降级。
- 每次线上测试完成后删除测试会话并复查数据不可访问。

完成标准：

- 浏览器 → API → PostgreSQL → 模型/降级 → 页面渲染全边界通过。
- Preview 连续三轮无 P0/P1 阻断。
- Production 发布后执行一轮只使用合成数据的冒烟测试。

### 阶段 E：安全加固并上线

#### E1. 身份与授权

- 为简历、诊断、匹配、面试、能力、改写、任务、申请和历史记录统一保存 `owner_key`。
- 登录用户使用 `user:<id>`；游客使用签名同意令牌派生的稳定匿名所有者。
- 所有读写删接口执行资源归属检查。
- Cookie 请求增加可信 Origin 校验，降低 CSRF 风险。

#### E2. 滥用与成本控制

- 使用 PostgreSQL 计数器实现跨实例、按 IP/所有者/接口的滑动窗口限流。
- 对诊断、面试、改写和求职信设置每日调用预算。
- 返回标准 429 和可重试时间；前端显示明确提示。
- 管理接口与普通 API 采用独立、更严格的限流策略。

#### E3. 文件与内容安全

- 扩展名、MIME 和文件签名三重校验。
- 限制文件大小、PDF 页数、DOCX 解压后大小、压缩比和提取文本长度。
- 拒绝宏文档、嵌套压缩包、路径穿越条目、加密文件和格式伪装。
- 临时文件使用随机隔离目录并保证请求结束清理。

#### E4. 数据与运维安全

- 删除操作使用数据库事务并覆盖所有关联表。
- 管理口令使用常量时间比较；生产缺少管理口令时禁用管理员接口。
- 增加 CSP、`X-Content-Type-Options`、`Referrer-Policy`、`Permissions-Policy` 和框架限制。
- 日志只记录哈希化标识、状态、延迟和错误类型，不记录简历/JD/回答正文。
- CI 的依赖漏洞扫描改为阻断高危漏洞，并补充安全测试。

完成标准：

- 越权、伪造会话、批量请求、超预算、恶意文件和删除残留测试全部通过。
- Preview 安全测试通过后再进入 Production。

### 阶段 F：G8/G9 与最终交付

- 生成 Preview/Production 验收证据和截图。
- 完成提交文件命名、大小、链接、版本和 commit 校验。

- 确认正式提交及比赛平台上的不可逆操作。

## 5. 发布门禁

只有同时满足以下条件才可合并和上线：

1. 本地全量 Python/Node 测试通过。
2. 新增 P0 回归和安全测试通过。
3. 依赖高危漏洞为零，或存在已记录且经用户接受的例外。
4. Preview 构建为 `READY`。
5. Preview F1→F5 完整浏览器闭环通过。
6. PostgreSQL 归属隔离和完整删除通过。
7. Preview 最近一小时无新增运行时错误。
8. PR 检查通过后合并 `main`。
9. Production 冒烟测试通过；失败立即回滚到 `792fd571`。
