## 1. 扩面一：活文档路径门禁 → 脚本层

### 1.1 「扩到 `js/*.js`」还不够

6b-3 把 `architecture.md` 里那处 `kb.js` 陈旧引用记进 Phase 7，理由是"活文档路径门禁只覆盖
`pages/*.html`"。但真正去看那一行时发现它写的是：

    （`public/js/data-bridge.js:12` 的 `ENDPOINTS` 映射 + `account.js` + `kb.js`）：

—— `kb.js` **不带 `js/` 前缀**。所以哪怕把正则从 `pages/*.html` 扩成 `pages|js`，
**它依然躲得过去**。这不是"范围不够宽"，是"写法没被算进观察面"。

所以 7a 的扩面收三种形态：

| 形态 | 例子 | 存在性对照 |
| --- | --- | --- |
| 页面 | `pages/target-job.html` | `public/pages/` |
| 脚本（带目录） | `public/js/data-bridge.js`、`js/radar.js` | `public/js/` |
| 脚本（**裸名**） | `kb.js`、`radar.js` | 全仓 `*.js` 基名 |

裸名规则锚在**反引号**上（活文档提到脚本名一律加反引号），这样既不误伤散文，也不会把
`tests/test_job_upload.js`（含 `/`）当成裸名。`*.json` 不会被吞成 `*.js`：正则结尾要词边界，
而 `.json` 里 `s` 后面紧跟的 `o` 仍是词字符 —— 这个坑在写脚本时用探针实测过一次。

裸名要扫全仓而不是只看 `public/js/`：活文档里也会指 `echarts.min.js`（在
`public/assets/vendor/`）或 `test_publish_mirror.js`（在 `tests/`）。判据要问的是
"这个名字还存不存在"，不是"它属不属于某个特定目录"—— 后者会制造一批假阳性，
而假阳性会让下一个人把这条判据删掉。

### 1.3 判据太窄 —— 6b-3 那条教训的镜像

6b-3 记了一条：**判据的观察面比它要判的语义宽**（`includes('localStorage')` 扫全文，
命中的是文件头那句"本文件不读 localStorage"，逼人去删掉最该留下的安全说明）。

7a 撞上的是它的**镜像**：观察面比语义**窄**。

> `product-scope.md` §2 那一行写的是「✅ **已整条删除**」。
> 判据的字面词表里只有「已删除」—— `"已删除" in "已整条删除"` 为 **False**。
> 于是一条**完全正确的**历史注记被判成漂移。

危害不是"多报一条"：**下一个人看到它红了，会去改那句话，而不是改判据。** 这类判据会把
正确的东西越改越错。

修法是给标记加一层同义容忍正则，并且**只容忍同义，不容忍近义**：

    已(?:于 <不含标点的状语>)?(?:整条|整块|全部|整体)?(?:删除|删掉|移除|退役|下线|废弃|作废)

- `已于 2026-09-13 整条删除` ✅ 认（动词前夹日期是最常见的写法）
- 「删除 `A` + `B`」❌ 不认 —— 那是**动作条目**（要去删），不是"已经删掉了"。
  这条边界由**两个相反方向的探针**钉住（探针 6 认"已整条删除"、探针 7 拒裸"删除"）。

刻意**没**放进来的是「快照」。6b-2b 实测过 —— 把 §2 标题写成「（快照：8 个 HTML）」
会让整节落进豁免区，从此那一节里的真漂移再也抓不到。快照是**范围说明**，不是**历史结论**。
`product-scope.md §1` 的标题就是「（快照：7 项导航、5 项带代号）」，它至今没有豁免作用，
这是有意保留的。

## 2. 扩面二：端点计数退役 → 三段不变量

### 2.1 那份手抄清单烂到了什么程度

`architecture.md §3` 长期挂着「**前端实际消费 15 个端点**」+ 15 个名字。实测：

- 15 个名字里 `uploadJD` / `submitJD` / `matchJD` / `majorMatch` / `tasks` **五个已退役**
  （前三个随 Phase 6b-1 的 `js/job-upload.js` 退役，`majorMatch` 与 `tasks` 随 Phase 1 的
  F2 / 专业匹配整块删除）；
- `/api/profile`、`/api/target-jobs`、`/api/actions` 三组 Phase 3/4 新增的端点**一个都没列**；
- 而"来源"一栏里还写着 `kb.js` —— 该文件早已删除。

同一节的路由表另有 7 条 Phase 1 就已删除的路由仍作为现状列着（`/api/f2/*`、`/api/f2_major`、
`/api/knowledge/*`、`/api/tasks*`、`/api/wf04/asr`），以及两个从未实测过的数字
（「40 条本地路由，48 条 Vercel 重写」；实测 **49 / 44**）。

这不是"某次忘了更新"，是**手抄的计数天然会漂**：它没有任何机制保证它跟代码同步。
所以 7a 的处置是**把这句话删掉**，换成可判据的不变量 ——

### 2.2 三段链

```
前端字面量  ⊆  vercel 重写源  ⊆  route_api() 处理分支
```

| 段 | 判据 | 判法 |
| --- | --- | --- |
| 前端字面量 ⊆ 重写源 | `scripts/frontend-api-literal-check.py`（**新**） | 静态：扫 `public/js/*.js` 里写死的 `/api/...` 与 `api('/...')` 参数 |
| 重写源 ⊆ 处理分支 | `scripts/vercel-dead-routes.py`（既有） | 实证：逐条重写按方法真发一次请求，看是否落到兜底 404 |
| 活文档路径真实存在 | `scripts/live-doc-path-check.py`（本轮扩面） | §1 |

`architecture.md §3` 现在只负责描述**分组与含义**，条数一律交给脚本打印；那 15 个名字的清单
改成"以 `public/js/data-bridge.js` 的 `ENDPOINTS` 为唯一来源，不在文档里另抄"。

### 2.3 新判据的观察面 —— 以及它**不**看什么

只看两处，写进脚本文件头：

- **A.** 任何形如 `'/api/...'` 的字符串字面量；
- **B.** 本地 `api()` 辅助函数的**整段参数表**内的相对字面量。

B 之所以要"整段"而不是"第一个参数"：`account.js` 里写的是

    api(isRegister ? '/auth/register' : '/auth/login', { method: 'POST', body: payload })

第一个参数是三元表达式，只取"第一个字面量"会**漏掉 `/auth/login`**。第一版探测脚本正是
这么漏的（报 20 条，实为 22 条）。探针 4 现在专门钉这一点。

**明确不看**：`ENDPOINTS.targetJobs + '/' + id` 这类**拼出来的**动态段。它没有可静态校验的
字面量 —— 要有意义地判它得在 VM 里桩掉 `fetch` 真跑一遍，那是集成测试的量级。本步只对
"写死的路径"负责，而写死正是最容易腐烂的那一类。**这条盲区写在脚本文件头**，免得下一个人
以为它管得比实际宽（这正是本项目反复栽过的那个坑）。

当前实测：15 个前端 js、**22 个写死的 `/api` 路径**，全部落在 38 条 vercel API 重写源内。

## 3. 扩面三：`.env.example` 与代码读取点双向一致

### 3.1 打开文件时发现的三类毛病

1. **有一行未注释的 `====` 分隔符**（第 30 行）—— 它会被当成一行非法内容；
2. **一整块重复**：`DUMATE_CONSENT_SECRET` / `DUMATE_CONSENT_MAX_AGE_SECONDS` 各出现 **3 次**，

3. **漏掉了 13 个代码里真的在读取的变量**。

第 3 类才是危险的：**模板短了，不会红。**

**29 个变量、无重复、每行合法**，变量描述改用「文件 + 符号名」而不是行号 ——
行号本身就是一种会漂的引用。

### 3.3 判据与白名单

`scripts/env-example-check.py` 双向判：

1. 每行只能是空行 / `#` 注释 / `NAME=VALUE`；
2. 每个变量名恰好一次；
3. 模板里的每个变量都要有消费者（否则是废弃变量）；
4. 代码里读的每个变量都要在模板里。

第 4 条留了白名单 `NOT_DOCUMENTED`，当前 4 条（`GITHUB_TOKEN`、`P0_MODEL`、
`QIANFAN_ACCESS_KEY`、`QIANFAN_SECRET_KEY`），**每条都必须写理由**，指向各自的一次性脚本。
白名单另有一条自检：**名单里的键必须真的还在被读取** —— 否则说明它已经腐烂成一张护身符，
应当删掉。这是"豁免名单要有边界"在 env 上的实现（对照 6b-3 的 D7 豁免名单恰好一项）。

**一次自指误报**：第一版把观察面打在 `scripts/` 全体上，于是脚本**自己的探针与文档字符串**
里的 `os.environ.get("A_ONE")` 被当成了真实读取点，报了 4 条。修法是显式排除自身，并把这个
理由写进代码（`SKIP_FILES`）。

## 4. `HANDOFF.md` 退役为薄指针

### 4.1 它烂成了什么样

原文件是一份"当前阶段事实声明"，维护着：当前阶段名、当前 commit hash（`672102b`，
**2026-08-01**）、里程碑表、未完成项清单 12 条、回滚点表 6 条、测试数字。
此后仓库走了 Phase 1 ~ 6b-3 十几个阶段 —— 也就是说：

- 「当前 commit」停在 6 周前；
- 「下一唯一任务」是"接通千帆 embedding 主路径…运行 `python tools/match_requirements.py
  --backend embedding …`"，而该脚本的参数早已不是这个形态；
- 「未完成项」里过半已经完成，而 Phase 3~6b 的工作一项都没进去。

### 4.2 决策：不重写，退役

两个选项：(a) 把它更新到当前状态；(b) 让它变成指针。选 **(b)**。

理由是 7a 反复遇到的那件事：**真相源多一份，就多一份会腐烂的副本。** 更新它只会重置
倒计时 —— 它上次被更新是 6 周前，不是因为有人偷懒，而是因为**它没有触发条件**：
没有任何判据、任何流程在它过期时报错。既然如此，正确的动作是把状态交给**本来就在被维护**
的地方（`product-scope.md`、`architecture.md`、`dependency-map.md`、`CHANGELOG.md`、
`docs/phase*-report.md`），HANDOFF 只留"去哪里找"。

### 4.3 判据

`tests/test_phase7a_contract.js` 判两件事：

1. **不得出现 40 位 commit hash、不得出现测试计数**（`N passed` / `N 项通过`）——
   这两类正是"当前状态"的载体。探针正反各验一次（短 hash `672102b` 与 `Phase 6b-3`
   里的数字不得误报）。
2. **它指到的每个仓库内路径都真实存在**（当前 32 个）—— 指针本身也会烂，所以它得
   落在判据的观察面里。抽取规则刻意排除"指某类文件"的写法：正文里「非 `.md` 文件」的
   `.md` 是扩展名不是路径（第一版实测把它当成了缺失文件）。

### 8.2 本轮明确不动的

- **不改写历史报告**（`docs/phase*-report.md`、`CHANGELOG.md` 已有条目）—— 沿用既定口径。
  §5 的勘误是"在现行文档里记"，不是"回去改历史"。
- **`public/*.md` 一份没动** —— 属 7b，是产品 / 隐私决策。
- **`/api/wf03/*` 一行没删** —— 属 7b。
- **文档里的 `docs/design/` 历史设计文档未归并** —— `architecture.md` 顶部把它标为
  "已过期，Phase 7 归并"；本轮没做，属 7b/7d 的收尾。

### 8.3 可复用的三条

1. **判据的观察面要覆盖作者真实会写的写法。** 6b-3 是观察面**太宽**（把注释当实现），
   7a 是**太窄**（「已整条删除」不认「已删除」）。宽和窄同样失效，而且窄的那一侧更阴 ——
   它红了会引导人去改**正确的东西**。
2. **判据的盲区要写在文件头。** 端点判据不看拼出来的动态段、env 判据不看 `tests/` ——
   这两条都写在脚本文件头。不写，下一个人会以为它管得比实际宽。
3. **不要把"当前状态"抄第二份。** 手抄的计数、`HANDOFF.md`、模板里的行号引用，
   都是同一类东西：**它们没有触发条件**，所以只会漂。要么给它判据，要么删掉它。
