## 1. 一句话

**判据从"看着 8 份文档"扩到"看着 56 份"，当场报出 162 处死链；全部修到 0，并且这次扩面
本身被做成了一个可判对象 —— `contracts/living-docs.json`。**

引用数从 **436 处**涨到 **955 处**（其中 **825 处存在**、130 处处于历史语境、0 死链）。
这个"涨"不是新写了引用，而是**同一批文档终于被看全了**：8 份变 56 份，
扩面前判据只看到 `436 / 955 ≈ 46%` 的引用。

这一轮的风险不在业务逻辑（一行没改），而在**三个方向的偏差**：

| 偏差 | 为什么它躲得过既有判据 | 现在谁看着 |
| --- | --- | --- |
| 观察面**比实仓窄**（新加的 md 没人看） | 判据只会报"我看到的那些引用"，看不到"我没看哪些文件" | `live-doc-path-check.py` 自检 B + 门禁第 10 步 |
| 清单与实仓**漂移**（幽灵条目 / 失效 glob / **空判豁免**） | 前两种判据自己能看见，**后一种是空判**：清单照样合法，那条规则却不再约束任何东西 | 门禁第 **16** 步（独立复算，不 import 判据） |
| 清单**坏掉就悄悄降级**回写死的 8 份 | 判据会继续绿，而它看的已经不是清单说的那个观察面 | `load_manifest()` 不降级 + 契约测试 |

Phase 7 把**结构**拆完了（`tools/` 归并、`api/index.py` 切分），但判据的观察面一直停在
「5 份 → 8 份」。结构越干净，观察面窄这件事越贵：仓库里 56 份文档在描述"现在是什么样"，
而只有 8 份会被检查。Phase 8 补的就是这一段。

## 2. 观察面成了一个可判对象

### 2.1 为什么不是"再往判据里多写 48 行"

7d 之前的形态是 `LIVING_DOCS = ["HANDOFF.md", ...]` 写在判据源码里。这种写法的两个后果：

1. **收谁进去是隐式决定** —— 没有一处地方写着"为什么这份是活文档、那份不是"，
   下一个人加文档时无从判断该不该加，只能照抄或漏掉；
2. **判据自己成了"谁是活文档"的唯一权威** —— 而它同时又是判据，于是"该看哪些文件"
   这件事**不可审**：你说漏了一份，它没法回应，因为它就是规格本身。

`contracts/living-docs.json` 把这件事挪出来，构成三层：**清单是规格 → 判据是执行 →
契约测试判"判据真的在读清单"**。

### 2.2 清单（`contracts/living-docs.json`，114 行）

| 组 | 条数 | 形态 | 为什么必须写理由 |
| --- | --- | --- | --- |
| `living` | **56** | 逐条 `path` | 一条说不出理由的登记，下一个人只会照抄或删掉 |
| `historical` | **17** | 逐条 `glob` | 豁免族是最容易被滥用的一类规则，每条都得说清"它冻结的是哪段时间" |
| `mirrors` | **14** | 逐对 `a`/`b` | **同名 ≠ 镜像**，必须逐对登记 |
| `excluded_forms` | 3 | 形态 + 理由 | "不判"这件事同样要有判据 |
| `precedence` | — | 一句裁决 | `living` 与 `historical` 重叠时谁赢 |

三条**刻意**的设计：

- **`mirrors` 逐对登记，不用"同名即应逐字节一致"那条规则。** `docs/index.md` 与
  `public/index.md` 同名同目录名，但内容不同 —— 前者是 docs 目录索引，后者是发布树公开清单。
  按名字配对会把这两份毁掉一份。清单里专门写了一行 `why_note` 说明这一对**不是**镜像。
- **`excluded_forms` 明写"刻意不收"的三种形态**，`why` 里给了实测数：
  裸 `.py`/`.md` 名实测 23 处，其中 6 处属"计划产出"、4 处属"仓库外脚本"。
  **不写在清单里的理由，下一个人会把"不收"读成"漏了"。**
- **观察面不再含"文件数量"这类会漂移的断言。** 清单只列路径，数量由判据每次算出来打印。

### 2.3 判据改成读清单，并补三条**双向**自检

`scripts/live-doc-path-check.py`：181 行改动（+181 / −17）。模块级常量
`LIVING_DOCS` / `HISTORICAL` / `MIRRORS` 清空为 `[]`，由新增的 `load_manifest(root)` 填充。

**`load_manifest()` 在清单缺失或不是合法 JSON 时，不降级、不返回默认值** —— 它返回问题列表，
`main()` 把它算进 FAIL。这是刻意的：**"悄悄退回写死的 8 份"正是 7d 那种"看着很宽其实只看了 8 份"
的状态**，宁可红，也不要回到那里。变异表里有两条专门证明这一点（清单挪走、清单写成非法 JSON）。

三条自检都是**双向**的（这条经验来自 7b 的「公开范围」：单向的清单只会往一个方向失效）：

| 自检 | 单向写法会漏掉什么 | 现在判什么 |
| --- | --- | --- |
| A 清单条目必须存在 | 只查"实仓有没有漏"→ 幽灵条目留着 | 清单的每一条都必须在实仓里落得下 |
| B 含引用的 md 必须登记 | 只查"清单里的对不对"→ 新文档永远不被看 | 实仓里每一份**含引用的** md 都必须在清单里 |
| C 每条 `historical` glob 至少命中 1 个文件 | 只查"glob 语法对不对"→ 写错一条就成了装饰 | 豁免族必须真的在豁免东西 |

另有探针 17/18/19 三条，钉住最容易回退的三处语义：`deliverables/**` 必须能豁免**深层**文件
（`fnmatch` 的 `*` 跨 `/`）、`living` 必须优先于 `historical`、以及
`docs/index.md` 与 `public/index.md` **必须被判为不一致**（防止"同名即镜像"的假设回来）。

### 2.4 新增门禁第 16 步：**独立复算**

`scripts/living-docs-scope-check.py`（197 行，**不 import 判据**，只用 stdlib）。

为什么必须另写一份：**同一份实现自查，只能证明"它和自己一致"。** 第 10 步的自检 A/B/C 是
判据"自己查自己"，而第 16 步用另一套代码判同一个对象。它专门覆盖第 10 步**看不见**的两种形态：

- **空判豁免**：某条 `historical` glob 命中的文件**全部**已是 `living`，那它一个文件都没豁免 ——
  它写在那里像一条规则，实际不约束任何东西。第 10 步的自检 C 只要求"命中 ≥1"，所以看不见这种。
- **观察面被吞成空集**：`living` / `historical` / `mirrors` 三组任一为空，让整份清单的
  五条结构契约**都为空判**。

另有第 16 步独有的**反向控制探针**：`docs/index.md` 与 `public/index.md` 必须内容不同。
少了它，第 16 步的"镜像逐字节比对"全绿可能只是因为那个比对恒真（路径拼错、读的其实是同一份文件）。

这是本轮第一次真跑就撞上的一条，值得单列：

`work/rewrite8-links.py` 第一版用「文本里出现过旧路径」当条件，干跑报 **182 处**，
其中包含 `tools/knowledge.py` —— 那是一处**账本里的历史引用**，判据刻意豁免了它
（它写着"保留为内部题库"，是 7d 归并时的处置记录）。第一版会把这句注记改掉，
**等于篡改记录**。

**只改 `verdict == "offender"` 的位置**。改完后 `tools/knowledge.py` 归零 —— 正好证明豁免生效。

> 口径：**"修链"和"判链"若是两套逻辑，就一定会在某一处错开。** 错开的方向要么是
> 改了不该改的（篡改历史），要么是漏改了该改的（判据继续红）。共用判定函数是唯一稳的做法。

## 4. 本轮踩到的三处真问题

### 4.1 「全仓代码 0 引用」是**单方向**的计数

D5 的立论依据是 `docs/dependency-map.md` §4.7 那句「`workflows/`（7 文件 ~1519 行）：
**全仓代码 0 引用**」。它是对的 —— 如果"引用"只算 `import`。它漏掉了另外三条真实在用的引用面：

| 引用面 | 证据 | 按「0 引用」归档会破坏什么 |
| --- | --- | --- |
| 答辩证据链 | `docs/defense-evidence-index.md` 与 `public/` 镜像的 Q10 / Q11 / Q15 / Q22 / Q26 直接指向 `workflows/wf-06-ops.md`、`wf-04-interview.md` | 评委按索引翻不到证据原文 |
| 冻结清单 | `scripts/p0-07-freeze.py` 把 `workflows/*.md`、`deliverables/**/*` 显式登记为冻结交付组 | 冻结清单指向空目录，交付包不完整 |
| 运行期写路径 | `scripts/run-wf-e2e.py`、`run-rehearsal.py`、`p0-05/06/07`、`backup-sessions.py` 默认往 `deliverables/` 下写（如 `deliverables/wf-evidence-<date>/rehearsal-10x.json`） | 脚本下次运行即失败 |

**而且 `workflows/*.md` 不是"只读说明书"**：它的正文里是可执行命令
（`python domain/validate_schema.py --schema …`、`python domain/redflag.py …`、
`python -m pytest tests/test_contracts.py`），上面 3.1 那 146 处重定向里有一大块就落在它身上。
**一个会被判据追踪、必须随重构同步的文件，不是死重。**

这与 7b 的 wf03 是同一类教训 —— **判据统计不到的引用面，不等于引用不存在。**
结论：D5 / D6 一律**保留原地、不归档**，体积口径让位于证据完整性。详见
`docs/product-scope.md` §10.6（含三条证据表）。

### 4.2 判据的**接口**变了，调用方要跟着变

门禁首轮跑出来 **1 failed / 510 passed**：

```
FAILED tests/test_phase7d_contract.py::test_live_doc_judge_covers_the_path_form
```

它断言 `HANDOFF.md`、`contracts/README.md`、`contracts/scoring.md` 在 `judge.LIVING_DOCS` 里。
Phase 8 之后 `LIVING_DOCS` 不再是模块级字面量，而是 `load_manifest()` 的产物 ——
只 `exec_module` 而不装载，它是**空列表**，于是失败信息读起来像"7d 的缺口回来了"，
其实只是装配少了一步。

修法：把 `_load_live_doc_judge()` 从"加载模块"改成"加载模块 **并完成清单装载**"，
且装载报错时**直接 assert 失败**（清单坏了却让测试继续跑，等于在测一个空的观察面）。

> 这是 7c 那类"读源码的静态断言"失效的**同一族**：判据的接口变了，调用方必须跟着变。
> 两次都说明一件事 —— **测试里对被测对象的"装配"步骤，本身就是接口的一部分，需要被显式写下来。**

### 4.3 裸名 `.py` / `.md` 洞：**刻意不扩面**

7a 给反引号内的裸 `*.js` 补过洞，但裸 `*.py` / `*.md` 两边都不管
（判据的 `PY_PATH_RE` 要求带目录）。实测 **23 处**，其中只有 1 处在观察面内
（`docs/architecture.md:199` 的 `task_service.py`）。

**决定不收，理由写进了清单的 `excluded_forms`**：同一个写法混了三种语义 ——
① 现在该存在的文件；② 计划产出的文件名（`deliverables` 表里的 `share-url.md`、
`freeze-checklist.md` 是"待产出"）；③ 仓库外的脚本（`mutate7d.py`、`patch6b.py` 住在 `work/` 那层）。
判据分辨不了这三种，收了就是**制造假阳性，而假阳性会让下一个人把整条判据删掉**
（7d 实测过：第一版扩面报 68 处，其中 7 处是假阳性）。
**"不收"是一个决定，不是一个遗漏 —— 它在清单里有位置、有理由、有实测数。**

## 5. 判据自检与变异测试

### 5.1 判据自检（正面证据，防止"恒绿"）

第 10 步的 `main()` 现在带 **19 条探针 + 3 条清单自检**，每条都对应一个"曾经真实失效过"的形态
（探针 1~16 来自 6b-2b / 7a / 7b / 7c / 7d，17~19 是 Phase 8 新增）。
第 16 步另带 5 条结构契约 + 1 条反向控制探针。

**空判防线**（Phase 8 补的，6 条）：第 10 步在观察面塌陷时会主动报错，而不是报 OK ——
活文档少于阈值、路径引用少于阈值、`pages/*.html` 数为 0、js 数为 0、顶层目录数过少、
`path` 类可解析文件数过少，任一出现即红。第 16 步同样要求 `living` / `historical` / `mirrors`
三组非空。**这些是"判据被删空却仍然绿"的唯一防线。**

### 5.2 变异注入（`work/mutate8.py`，**15/15 全部被抓到**）

15 条注入，10 条正控 + 4 条反向控制 + 1 条回归控制。
**恢复一律用字节快照回放，绝不用 `git checkout`** —— 6b-3 那次 `git checkout -- public/index.html`
回到的是 HEAD，把尚未提交的改动一起冲掉了；本脚本面对的永远是未提交的工作区。

| 1 | 清单里 `living` 指向不存在的文件 | 第 16 步（幽灵条目） |
| 2 | 清单里 `historical` glob 命中 0 个文件 | 第 16 步（失效 glob） |
| 3 | 清单里 glob 命中的文件**全部已是 `living`** | 第 16 步（**空判豁免**） |
| 4 | `living` 条目去掉 `why` | 第 16 步（缺理由） |
| 5 | 只改镜像的一侧 | 第 16 步（镜像漂移） |

| R3 | 历史族里写已消失的旧路径 | 第 10 步**必须仍然绿**（豁免族真在豁免） |
| R4 | 清单里加一个无关字段 | 第 16 步**必须仍然绿**（不是"恒红"） |
| G1 | 在根目录重建空的 `tools/` | 第 15 步 shell 分支（7d 成果不回潮） |

第 3 条是本轮**最重要的一条**：它是唯一一条"判据看不见、只有第 16 步能抓"的形态。
第 7 / 8 条证明"清单坏掉不许降级"。R1~R4 证明四条新判据都不是恒红。
G1 是回归控制：Phase 8 的改动不得让 7d 的 `tools/` 归并成果回流（**空目录也要红** ——
它会让 `tools` 变成可 import 的命名空间包）。

**变异脚本自己踩的三个坑**（首次真跑 **12/15**，逐条查下来**判据一条都没坏**）。
三个坑是同一族：**变异脚本自身的错误会伪装成"判据失效"**，而账最终记在判据头上。

1. **表里的 `REPLACE` 形态必须显式列进 `apply_mutation`。** 7d 起的字段约定是
   `(说明, <文件路径>, <锚点>, <替换文本>, 判据, 特征串)` —— 默认分支的"目标"位置放的是
   **文件路径**。漏掉 `REPLACE` 分支时，字面量 `"REPLACE"` 被当成路径，脚本去开一个名为
   `REPO/REPLACE` 的文件并抛 `FileNotFoundError`。一次踩了 **6 行**。
2. **"新建一个文件"这种形态不要用。** 它需要额外的"删除"能力，而实测那次新建出来的文件
   **没被恢复掉**，还**污染了后面 4 行的判据输出** —— 判据因为"未登记的探针文件"而红，
   报出来的却不是那几行期望的特征串，于是 **4 条正确的注入被记成 MISS**。
   改法：把"漏登记"改成一个 living 文档 `MOVE` 到没登记的名字上，
   **复用已经验证过的恢复路径**。教训：**恢复路径越少越好**。
3. **注入的落点要用判据自己验一遍。** 判据的历史语境词表沿**父子标题链遗传**，
   所以同一行 `tools/…` 落在「Phase 7d 完成记录」底下会被**合法**豁免、落在别处才是 offender。
   首次真跑把"死链"这条追加到 `docs/product-scope.md` 末尾（那一节的父标题里就有「完成记录」），
   判据**正确地**没红（豁免数 130→131，那正是新注入的这一处）—— 表现却是"MISS 判据失效"。
   本次的落点（`workflows/wf-06-ops.md`）是先用判据的 `classify()` 实测过
   "追加到末尾判 offender"才写进表的。这与 7d 那条"锚点落在注释上 = 空操作"是同一族。

> 口径：**变异测试的失败信息指向的永远是判据**，但根因有一半在变异脚本自己。
> 三个坑的共同修法是同一条纪律 —— **施加变异之前，先让判据自己确认"这一处应该红/应该绿"**。

### 7.2 遗留

  这是设计如此 —— **把"该不该收进观察面"变成一个每次都必须回答的问题，而不是一次性的决定。**

### 7.3 三条可复用的

1. **清单化 ≠ 可判。** 把隐式集合写成清单只是第一步；必须再有"清单 vs 实仓双向比对"，
   否则幽灵条目和漏登记各占一半概率。见 `judgeable-allowlist-gate` 那套做法。
2. **空判防线要单列。** "规则存在但不再约束任何东西"（空判豁免、观察面为空）
   是绿着失效的最隐蔽形态，必须在同一处显式判它。
3. **修法与判据共用同一判定函数。** 两套逻辑一定会在某处错开，方向不外乎"改了不该改的"
   或"漏改了该改的"（§3.3 实测）。
