# 职业教练 · 个人账号与历史记录功能规划（2026-08-06）

> 状态：规划 + 交互原型演示（待确认后进入后端实现）

## 一、目标与用户故事

让用户从"用完即走"变成"有归属感的个人空间"：

1. 注册后拥有自己的账户（手机号 + 邮箱 + 登录密码 + 账户名），下次回来资料和历史都在；
2. 页面左侧新增**可伸缩侧边栏**：显示当前账户、历史检测记录；
3. 每一次检测（F1 简历诊断 / F2 岗位匹配 / F3 模拟面试 / F4 能力报告）自动存档进历史，可随时回看。

## 二、本期范围

**做**：注册 / 登录 / 登出、会话绑定用户、历史记录自动落库、侧边栏（可伸缩）、记录回看、单条删除 / 清空、多用户数据隔离。

**不做（本期）**：短信/邮箱验证码发送、找回密码、第三方登录、多人协作、会员与付费、多设备同步。

## 三、需要先澄清的一个设计点（重要）

你提到"邮箱密码注册"。这里存在安全歧义，必须先纠正：

- ❌ **不要**让用户填写邮箱本身的密码作为平台密码——平台无法验证也不应存储邮箱密码，属于高危反模式；
- ✅ 正确方案：注册表单里是"**设置平台登录密码**"，与邮箱密码无关。字段可以叫"邮箱密码"（指"与邮箱一起注册时设置的密码"），但必须明确提示"勿使用邮箱本身的密码"。

演示原型已按此处理（placeholder 有提示），后端实现同样按"平台自设密码 + bcrypt 哈希"落地。

## 四、产品设计

### 4.1 侧边栏

| 状态 | 行为 |
|---|---|
| 桌面展开 | 宽 260px，显示用户卡 + 历史列表 |
| 桌面收起 | 宽 64px，只显示图标（头像 / 历史），hover 展开 |
| 移动端 | 抽屉式，从左侧滑出，遮罩点击关闭 |
| 未登录 | 用户卡显示"未登录游客" + 登录/注册按钮；历史为空态引导 |
| 已登录 | 显示账户名（首字头像）、手机号/邮箱脱敏、退出按钮 |

历史记录分组：按类型（F1-F4）加日期倒序；每条显示标题、时间、状态；点击回看，支持单条删除与一键清空。

### 4.2 注册 / 登录表单

- 注册字段：手机号（11 位，格式+唯一）、邮箱（格式+唯一）、登录密码（≥8 位，字母+数字）、账户名（2-16 字符）；
- 登录：手机号 **或** 邮箱 + 密码；
- 错误提示逐字段内联；成功注册自动登录。

### 4.3 交互状态

- 未登录用户可正常使用全部功能，检测记录归属"游客会话"；
- 登录后游客会话自动合并到当前账户（以 session 为准）；
- 历史回看 = 携带原 session_id 打开对应 F1-F4 页面并恢复现场。

## 五、技术设计

### 5.1 数据模型（SQLite 新增三张表/字段）

```sql
CREATE TABLE users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  phone         TEXT UNIQUE NOT NULL,
  email         TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,            -- bcrypt，绝不存明文
  display_name  TEXT NOT NULL,
  created_at    TEXT NOT NULL,
  last_login_at TEXT
);

CREATE TABLE history_events (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL REFERENCES users(id),
  session_id TEXT NOT NULL,               -- 关联现有 wf01-06 会话数据
  event_type TEXT NOT NULL,               -- F1 / F2 / F3 / F4
  title      TEXT NOT NULL,
  status     TEXT NOT NULL,               -- done / partial / failed
  created_at TEXT NOT NULL
);
```

现有 `resumes / diagnoses / matches / interview_sessions / abilities` 继续以 `session_id` 为键，新增 `user_sessions(session_id, user_id)` 完成归属映射，避免大改现有表。

### 5.2 API 设计（新增 `/api/auth/*` 与 `/api/history/*`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | 校验四字段 → bcrypt 哈希 → 写 users → 自动登录 |
| POST | `/api/auth/login` | 手机号/邮箱 + 密码 → 签发会话 |
| POST | `/api/auth/logout` | 注销会话 |
| GET | `/api/auth/me` | 当前登录态与脱敏信息 |
| GET | `/api/history` | 分页拉取当前用户历史（type 过滤） |
| DELETE | `/api/history/:id` | 删除单条历史（级联删除会话数据，符合隐私设计） |

### 5.3 会话与安全

- 密码 bcrypt 哈希（cost=12），绝不落明文；
- 会话 Cookie：`HttpOnly + SameSite=Lax + Secure`，有效期 30 天；
- 登录态下 wf01-06 自动打 `user_id`；历史写入与读取必须校验归属；
- 注册/登录按 IP 限频（如 5 次/分钟）；手机号、邮箱唯一约束兜底；
- 手机号本期不做短信验证（无短信服务商），先做格式+唯一校验——如需真实验证，属于外部依赖项，需另行确认。

### 5.4 前端

- 新增 `ui/prototype/css/sidebar.css` + `js/account.js`，全站复用；
- 侧边栏组件：用户卡、历史列表、空态/加载态/错误态；
- data-bridge 统一携带会话令牌；历史回看注入 `?session=`；
- 移动端抽屉与桌面伸缩两套断点（900px）。

## 八、风险与边界

- 短信验证码：无短信服务商，本期仅格式+唯一校验（需用户确认是否接受）；
- "邮箱密码"歧义：已按"平台自设密码"落地，避免存储邮箱密码；
- 历史回看依赖会话数据仍在（Vercel `/tmp` 冷启动会清空）——生产应接外部数据库或定期备份（已有 backup-sessions.py）；
- 演示原型的数据仅存浏览器 localStorage，仅用于看效果，不代表最终安全实现。
