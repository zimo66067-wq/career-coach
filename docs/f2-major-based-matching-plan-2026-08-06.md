# F2 专业化 · 专业导向岗位匹配 规划（2026-08-06）

> 状态：调研完成 + 规划待决策（用户拍板后进入 R1）

## 一、目标

把 F2 从"简历 ↔ 用户上传 JD 的逐条匹配"升级为**专业视角 + JD 双视角**的专业化匹配：

1. 用户先选择（或确认）自己的本科专业，再拖入/上传简历；
2. 系统展示该专业的**对口工作**与**衍生工作**（含常见岗位与典型要求）；
3. 匹配结果结合专业契合度，不再对所有简历用同一套口径；
4. 支持无 JD 时按专业岗位画像匹配（方向推荐），有 JD 时保留逐条四态匹配并叠加专业维度。

## 二、调研结论（官方数据底座）

### 2.1 专业目录：教育部《普通高等学校本科专业目录》

- 2024 版：**12 个学科门类 / 93 个专业类 / 816 种专业**；
- 2025 版：**93 个专业类 / 845 种专业**（年度更新机制，2025 新增 29 种，如低空技术与工程、碳中和科学与工程、区域国别学、人工智能教育等）；
- 官方出处：教育部通知及《目录（2025年）》PDF 附件
  http://www.moe.gov.cn/srcsite/A08/moe_1034/s4930/202504/t20250422_1188239.html
- 专业结构：学科门类（12）→ 专业类（93）→ 专业（845），专业带 6 位专业代码，可直接程序化解析。

### 2.2 专业↔职业：人社部《职业信息与教育培训项目（专业）信息对应指引（2023年版）》

- 对应程度分 **6 级：强 / 较强 / 较弱 / 弱 / 无关 / 无对应**；
- 共 **9327 组对照**：普通本科 914 组、职业本科 1132 组、高职专科 3251 组，其余为中职/技工；
- 由《职业分类大典（2022年版）》修订专家委员会编制，2023 年中国劳动社会保障出版社出版。

### 2.3 职业↔岗位：《中华人民共和国职业分类大典（2022年版）》+ 2026 企业薪酬调查文件

- 大典四层结构：职业大类 / 中类 / 小类 / 细类，共 **1600+ 职业**，带编码；
- 人社部 2026 企业薪酬调查工作文件：1600+ 职业 → **常见市场岗位名称**（例：通信工程技术人员 → 5G 研发工程师、数据通信工程师；会计专业人员 → 会计/财务/出纳）；
- 机读化示例：GitHub leo4stone/ZHONGHUARENMINGONGHEGUOZHIYEFENLEIDADIAN（大典格式化数据，可作解析参考）。

### 2.4 术语映射（本产品口径）

| 产品术语 | 数据来源口径 |
|---|---|
| 对口工作 | 《指引》中 强 / 较强 对应职业 → 常见岗位 |
| 衍生工作 | 《指引》中 较弱 / 弱 对应职业 → 可迁移岗位 |
| 专业契合度 | 用户专业与 JD 所属职业画像的对应等级 |

## 三、产品流程（新 F2）

```
选专业 → 看岗位画像 → 拖入/上传简历 → 匹配 → 报告
```

1. **选专业**：学科门类 → 专业类 → 专业三级联动 + 搜索 + 最近选择；提供"不确定专业"入口（按求职意向反向推荐专业）；
2. **看画像**：展示该专业对口方向（岗位清单 + 典型职责/技能要求）与衍生方向（可迁移岗位）；
3. **传简历**：拖入/上传，沿用脱敏 + 同意门；
4. **匹配**（双模式）：
   - 模式 A「专业画像匹配」（无 JD）：简历 vs 对口/衍生岗位画像 → 方向推荐 + 每条画像覆盖度 + 缺口清单；
   - 模式 B「JD 精准匹配」（有 JD）：保留四态（covered/weak/missing/unknown）+ 证据验证器，叠加"专业契合度"（JD 归属岗位画像 ↔ 用户专业对应等级）；
5. **报告**：M 分升级为双维度（专业契合 + 岗位覆盖），缺口分级 P0/P1/P2，给出行动建议。

## 四、数据架构

| 表 | 内容 | 来源 |
|---|---|---|
| `majors` | 12 门类 → 93 专业类 → 845 专业（代码/名称/年份版本） | 教育部目录 2025 |

| 前端组件 | 专业选择器（三级联动 + 搜索 + 最近使用） | 自研 |

所有表带 `source` 与 `version` 字段，标注官方出处，便于审计与更新。

## 五、实施策略（回应"所有专业必须加入"）

- **数据层一次全量**：845 专业全部入库（教育部目录 PDF 程序化解析），专业→职业对照同步导入；
- **画像层分批**：首批覆盖布点数 Top 100 专业（覆盖绝大多数毕业生就业面），按专业类逐步扩展到全部；未覆盖专业显示"画像建设中"，降级为通用 JD 匹配（不阻塞使用）；
- **匹配层不动地基**：现有四态引擎与证据验证器保留，专业维度作为前置筛选与权重叠加；
- **与账号/历史联动**：所选专业存入用户档案与历史记录，二次使用免重选。

## 七、决策点（请拍板）

1. **画像生产方式**：LLM 生成 + 人工抽查（推荐，快且可质检）还是纯人工审核（准但慢）？
2. **模式 A（无 JD 的专业画像匹配）**：是否作为正式功能上线（有画像质量兜底），还是先只做引导？
3. **M 分口径**：双分制（专业契合 + 岗位覆盖）还是单一综合分？
4. **非本科用户**：大专/研究生/转行者本期是否覆盖？（建议先本科，后续扩职业本科与高职）
5. **数据边界**：官方数据免费可用并注明来源；如需薪资/热度等商业维度（如麦可思/智联数据）需另行授权，本期不做。
