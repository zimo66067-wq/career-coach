## 3. 定性反馈访谈问题

测试完成后，对每位参与者进行 5-10 分钟半结构化访谈。以下问题按优先级排列。

### 3.1 核心体验问题

1. 你觉得简历诊断的结果准不准？哪条建议你觉得最有用？哪条最没用？为什么？
2. JD 匹配列出的"缺口"是否符合你的实际感知？有没有明显遗漏或误判？
3. 模拟面试的追问是否自然？有没有让你觉得"这个追问很到位"或"这个追问莫名其妙"的时刻？
4. 七天计划你会真的去执行吗？如果不会，是计划本身的问题还是你的时间问题？
5. 雷达图上哪个维度的高低让你觉得"这个评估对"或"这个完全不对"？

### 3.2 产品方向问题

6. 如果只能保留一个功能（F1-F4），你会保留哪个？为什么？
7. 你愿意为这个工具付费吗？如果愿意，在什么价格区间？如果不愿意，缺什么让你不愿意？
8. 你觉得这个工具和你目前用的求职工具（如 BOSS 直聘、脉脉等）最大的区别是什么？
9. 你在使用过程中有没有哪个时刻觉得"卡住了"或"不知道该做什么"？
10. 如果你能加一个功能，你会加什么？

### 3.3 隐私与信任问题

11. 你在上传简历前有顾虑吗？去标识化处理的说明是否打消了你的顾虑？
12. 你注意到界面上的"简化匹配"或"简化诊断"标注了吗？你觉得这种标注有必要吗？

## 4. 数据分析框架

### 4.1 定量分析

- **描述性统计**：各指标的均值、中位数、P95、标准差
- **分布检查**：完成时间是否右偏（长尾用户特征）、评分分布是否双峰（极端满意/极端不满意）
- **相关性**：建议采纳率 vs 任务完成率、理解错误数 vs 主观满意度
- **降级影响**：降级组 vs 非降级组的各指标对比（注意小样本下不做显著性检验，仅看方向）

### 4.2 定性分析

- **主题编码**：对访谈回答进行开放式编码，归纳高频主题（如"追问太机械""缺口清单很实用""雷达图看不懂"等）
- **关键事件分析**：标记测试中发生的"顿悟时刻"（用户明显感到价值）和"流失时刻"（用户明显失去兴趣）
- **负面反馈优先**：负面反馈的修复优先级高于正面反馈的强化

### 4.3 结论判定标准

| 维度 | 通过标准 | 需改进 | 不通过 |
|------|----------|--------|--------|
| 任务完成率 | >= 80% | 60%-80% | < 60% |
| 虚构事实率 | 0% | N/A | > 0%（阻断） |
| 建议采纳率 | >= 60% | 40%-60% | < 40% |
| 主观满意度均分 | >= 3.5 | 2.5-3.5 | < 2.5 |
| 降级恢复时间 | <= 10s | 10-20s | > 20s |

### 4.4 小样本注意事项

- 样本量 N <= 30 时，**不做参数检验**（t 检验/卡方），仅报告描述性统计和方向性趋势
- 定量指标用于**纵向对比**（迭代前后），不用于横向断言
- 定性反馈权重高于定量指标：一个深度访谈洞察的迭代价值 > 10 个满意度评分
- 所有结论标注"小样本角色扮演，N = ___，不具备总体代表性"

## 5. 数据记录格式

每位参与者的完整记录应包含以下文件，存放于 `tests/user-research/` 目录：

```
tests/user-research/
├── participant-{NN}/
│   ├── consent.txt              # 签署的披露声明
│   ├── quantitative-metrics.json # 定量指标结构化记录
│   ├── interview-notes.md       # 定性访谈记录
│   └── feedback-summary.md      # 单人总结（3-5 句话）
├── aggregate-report.md          # 全部参与者汇总分析
└── README.md                    # 本模板说明
```
