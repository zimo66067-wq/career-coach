# F3 打字式对话面试 · 设计与技术方案

> 版本：v1.0 · 日期：2026-08-13 · 状态：已实施
> 变更：F3 由“语音增强 + 文字主链路”改为**纯打字对话式面试**，语音模块不再接入 F3。

## 1. 背景与目标

原 F3 存在两个问题：
1. 语音链路未闭环（识别结果不提交、TTS 空壳），且与主链路脱节；
2. 对话状态机存在断点：回答完追问后**不会自动进入下一主问题**，最多只能完成“第 1 题 + 1 次追问”。

本次改为纯打字对话式面试，目标：
- 系统先抛出问题，用户打字回答；
- 系统判断回答，输出“优点 / 不足 / 追问”即时反馈；
- 完整跑完 5 个主问题（每题最多 1 次追问）；
- 结束时自动生成综合报告：I 分、五维得分、优点总结、不足总结、下一步安排。

## 2. 对话流程（状态机）

```
[空态] 点击“开始面试”
   │  （自动获取 consent → POST /api/wf04/start）
   ▼
Q1 面试官提问（基于简历/JD 缺口，或题库降级）
   │  用户打字输入 → POST /api/wf04/stream
   ▼
系统解析回答（STAR 缺口 + 五维子分）
   │  输出即时反馈：优点 / 不足 / 追问
   ├─ 有缺口 → 追问 FQ1 → 用户回答追问 → 记录追问回答 → 进入 Q2
   └─ 无缺口 → 直接进入 Q2
   │  …（最多 5 个主问题，每题最多 1 次追问）
   ▼
Q5 完成 → POST /api/wf04/end
   ▼
综合报告：I 分 + 五维均分 + 优点总结 + 不足总结 + 下一步安排
```

## 3. 每轮即时反馈结构（evaluation）

后端在 SSE `done` 事件中携带 `evaluation`：

| 字段 | 含义 | 生成规则 |
|---|---|---|
| `strengths` | 优点（覆盖的 STAR 要素） | 六个要素（情境/任务/行动/结果/量化/反思）中**未缺失**者 |
| `weaknesses` | 不足（缺失要素） | 启发式检测出的缺失要素 |
| `subscores` | 五维子分 | 结构/相关/具体/追问适应/清晰（0-100） |
| `missing_elements` | 原始缺失标识 | 供追问与报告复用 |
| `answer_quote` | 回答引用 | 含数字句子优先，否则最长句 |

追问规则：存在缺失要素且本主问题尚未追问过 → 按优先级（行动 > 结果 > 量化 > 情境 > 任务 > 反思）生成 1 次追问。

## 4. 状态机断点修复（后端）

`POST /api/wf04/stream` 处理逻辑升级：

```
pending_followup = 会话存在待回答的追问（_current_followup 非空）
if pending_followup:
    result = submit_followup_answer(答案)      # 记录追问回答，并清空 _current_followup
    next_question = next_question(会话)        # 进入下一主问题
else:
    result = submit_answer(答案)               # 主问题回答 + STAR 解析
    if result.follow_up 非空:
        next_question = None                   # 等待用户回答追问
    else:
        next_question = next_question(会话)    # 无缺口，直接进入下一主问题
```

SSE `done` 事件新增 `nextQuestion`（{question, targets, done}）与 `evaluation`；
`done=true` 表示全部主问题完成，前端自动拉取报告。

## 5. 最终报告结构（POST /api/wf04/end）

1. **I 分与五维均分**（结构/相关/具体/追问适应/清晰）
2. **优点总结**：覆盖频率 ≥ 50% 的 STAR 要素 + 平均分 ≥ 65 的维度
3. **不足总结**：缺失频率 ≥ 30% 的 STAR 要素 + 平均分 < 60 的维度
4. **下一步安排**：依据高频缺口生成 3-5 条行动项（量化补充 / STAR 重写 / 项目复盘 / 复测面试 / 简历同步），衔接 F4 七天计划

## 6. 前端交互设计

| 视图 | 内容 |
|---|---|
| empty | 面试说明 + “开始面试” |
| processing | “面试官正在分析你的回答…” |
| success | 对话区（问题/回答/反馈气泡）+ 进度（第 N/5 题）+ 回答输入框（Ctrl+Enter 提交）+ 结束面试 |
| report | I 分、五维得分条、优点、不足、下一步安排 + “再练一次” |
| error | F3 专属错误说明 + “重新开始面试” |

气泡类型：
- 面试官问题（第 N 题，含考察点）
- 你的回答
- 即时反馈（优点 chips / 不足 chips / 子分）
- 面试官追问 / 下一题

- 空态点击“开始面试”→ 渲染第一问；

- Node：将 test_voice_ui.js 替换为 test_f3_chat_ui.js（断言 F3 不再引用语音元素，打字对话元素齐全，三树镜像一致）。

  1. 点击开始 → 面试官先提问；
  2. 打字回答 → 收到“优点/不足/追问”反馈；

  5. 页面无任何语音入口。
