## 2. F3 P0 修复明细

### 2.1 危险模型输出安全阀（对应 004 §7.1）

新增独立的 `InterviewEngine._check_unsafe_generated_question()`，与 HR 敏感词 `_check_sensitive()` 语义分离，命中即拒绝（fail closed）。拦截三类：

1. **提示注入**：`忽略/无视/绕过/跳过/覆盖/推翻/取消/忘记/丢弃 + 规则|指令|要求|设定|提示|约束|限制|策略|安全|角色|身份`；英文 `ignore/disregard/forget/bypass/override + rule|instruction|prompt|policy|guideline|safety|system`；以及 `系统提示词 / 开发者消息 / 内部指令 / 隐藏指令 / system prompt / developer message`。
2. **凭据索取**：`api key / apikey / 私钥 / 访问令牌 / .env / 数据库连接串 / 数据库备份` 直接命中；带请求动词的 `密码 / 口令 / 验证码 / 密钥 / 令牌 / token / 凭据 / 账号 / 环境变量 / 连接串`。
3. **PII 索取**：带请求动词的 `身份证 / 手机号 / 电话号码 / 邮箱 / 住址 / 银行卡 / 微信 / QQ / 支付宝 / 护照 / 社保`；无动词也拦截 `身份证号(码) / 银行卡号 / 护照号 / 社保号`。

检查点共三处，避免任何绕过路径：

- **闸门 A**：模型输出在拼接回答 anchor 之前检查；
- **闸门 B**：拼接 anchor 之后再次检查，防止把用户回答里的注入语句回显成题目；
- **闸门 C**：降级题 / 敏感词替换题之后再检查一次，异常时回落 `_hardcoded_safe_question()`——一条只使用已脱敏岗位标题、不索取敏感信息的硬编码题目；若岗位标题本身也不安全，直接回落到通用行为题第一题。

命中时设置 `session["degraded"] = True` 与 `session["unsafe_blocked"] = True`。

`_safe_answer_anchor()` 同时拒绝危险注入短句（与敏感词检查并列），因此危险 anchor 不会被回显。

### 2.2 模型上下文长度与脱敏闭环（对应 004 §7.2）

- `_safe_job_title()`：`job_title` 先 `deidentify` 再硬截断 120 字。
- `_safe_gap_payload()`：`target_gap` 按 `id ≤ 64 / type ≤ 32 / text ≤ 160 / status ≤ 16` 硬截断，`text` 先脱敏。
- `router.call()` 的 `context` 只保留 `turn_id`、`adaptive`、`must_reference_previous_answer` 三个有界标量；**不再回传原始 `gap`，也不再重复回传 `recent_turns`**（结构化内容已在 `user_input` JSON 中出现一次）。
- `_ensure_adaptive_question()` 与 `_adaptive_fallback_question()` 在引用 gap 原文前都先脱敏并检查敏感/危险，命中则不引用该 gap。
- `_safe_answer_anchor()` 收尾增加不变量：anchor 必须是原始回答的逐字子串，否则返回空串。
- `next_question()` 收尾增加不变量：若最终题目不再包含 anchor，则 `basis` 置空，保证「非空 basis 一定出现在题目中且是脱敏回答的子串」。

验收证据：新增测试用 10k 字岗位标题 + 10k 字 gap（内含「我叫王小明」「13800138000」）调用捕获型 router，断言 payload 长度 < 8000、不含手机号与姓名、含 `[REDACTED_PHONE]`、`target_gap` 各字段在上限内、`context` 键集合恰为上述三个标量且不含 `gap` / `recent_turns`。

### 2.3 中文姓名去标识化（对应 004 §7.3）

`tools/deidentify.py` 重构为三条只替换“姓名捕获组”的规则，不破坏句意：

1. `RE_NAME_FIELD`：「姓名：张三」显式字段（历史行为保留）。
2. `RE_NAME_SELF`：「我叫 / 我是 / 本人叫 / 本人是 / 名字叫 / 名字是」自述句式。
3. `RE_NAME_LINE`：整行只由一个姓名构成（简历抬头「王小明」）。

关键设计：

- 姓名长度用「单姓 + 1~2 字」或「复姓 + 1~2 字」限定，**不会吞掉紧随其后的词**（「我是王小明负责后端」只替换「王小明」）；
- `_looks_like_name()` 用姓氏表 + 复姓表 + 称谓词黑名单校验，因此「学生会」「财务经理」不会被误判；
- 兜底规则刻意收得很紧（仅“整行即姓名”），并带常见非姓名词保护（华为 / 周末 / 金融 等），避免把普通岗位或公司词误删——即 004 §7.3 第 3 条要求的“谨慎应用”。

验收证据：`姓名：王小明`、`我叫王小明`、`我是王小明`、`我是王小明负责后端`、手机号 / 邮箱 / 身份证均不再残留；`answer_quote` 仍是脱敏后 answer 的子串。

### 2.4 低 ASR 置信度不推进状态机（对应 004 §7.4）

- 抽出 `_advance_interview(engine, session, answer_text, asr_confidence)`，`/wf04/answer` 与 `/wf04/stream` 共用同一编排。
- `submit_followup_answer()` 新增 `asr_confidence` 参数，与主回答一致：置信度 < `ASR_MIN_CONFIDENCE`（0.75）时直接返回 `needs_confirmation=True`。
- 低置信度分支严格做到：不记录 turn、不生成追问、不调用 `next_question()`、不递增 `current_main`、保留当前题目与 targets、保留 `_current_followup`。
- SSE `done` 事件返回 `nextQuestion = null` 且 `needs_confirmation = true`，并向前端输出「请确认或修改转写文本后重新提交」提示。

验收证据：新增两个 API 级测试——低置信度后 `turns == []` 且 `current_main == 1`；存在待回答追问时低置信度不消费追问，之后一次正常回答仍被当作追问回答消费并推进到自适应下一主问题。

### 2.5 F3 边界加固（对应 004 §7.5）
