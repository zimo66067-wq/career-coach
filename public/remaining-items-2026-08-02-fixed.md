# AI求职面试教练待完善与修复报告

## 原始任务

检查“职业教练”仓库是否完全符合既定 G0–G9 路线；修复可在代码层闭环的问题，并将其余缺口形成可执行、可验收的待完善报告。

## 核心摘要

**结论：项目尚未完全符合设计路线，当前不能宣称交付完成。** 本轮发现原清单遗漏了一个 P0 阻塞：`QianfanModelRouter._try_call()` 实际为占位实现，仅配置 API Key 仍无法调用模型。本轮已补齐千帆 V2 Chat Completions 调用、修复真实 Schema 到旧前端视图的证据字段适配、删除面试引擎死代码，并增加离线契约验证。尚未闭环的关键事项集中在 DuMate 平台运行、真实模型复测、端到端真实数据、语音实机、G8 用户测试和 G9 提交冻结。

> 证据边界：历史记录为 187/187 测试通过；本轮环境未安装 pytest，因此该数字不是本轮重新验证结果。本轮仅确认 Python 编译、JavaScript 语法、路由请求契约、动态问题成功路径和字段适配断言通过。

## 二、仍需完善的 P0 项

### P0-01 真实模型调用与 7×3 稳定性复测

- **缺口：** 尚无真实 Key 下的调用日志、模型版本快照、耗时和失败率。
- **主方案：** 配置 `QIANFAN_API_KEY`，对 7 类任务各以同一输入运行 3 次，保存脱敏请求摘要、输出、模型名、延迟、trace_id。
- **备用方案：** 若千帆 V2 不可用，设置 DuMate 模型端点并走 `DuMateModelRouter`，执行同一评价表。
- **降级方案：** 比赛演示保留规则/题库输出，但必须显示“降级模式”，不得冒充实时 AI。
- **验收门槛：** 21 次调用均有证据；结构化输出有效率 ≥95%；失败有可见降级标记；敏感信息不落日志。

### P0-02 DuMate WF-01～WF-06 实际搭建

- **缺口：** 仓库只有合同与工具链，没有平台截图和导出物。
- **主方案：** 按合同逐个搭建、运行并导出六个工作流。
- **备用方案：** 平台不支持导出时，保存节点全景、关键节点配置、成功运行详情和时间戳。
- **降级方案：** 本地工具链用于演示，但提交材料必须明确“非平台运行证据”。
- **验收门槛：** 每个 WF 至少 1 次成功、1 次异常/降级记录；输入输出与 Schema 对齐；证据入库。

### P0-03 真实端到端数据闭环

- **缺口：** 未证明陌生简历上传 → 诊断 → JD 匹配 → 面试 → 雷达图/7 天计划全链路使用真实数据。
- **主方案：** 配置 `DUMATE_API_BASE`，用一份未进入 fixtures 的脱敏简历和 JD 完整运行。
- **备用方案：** 逐端点真实调用并以同一 `trace_id/session_id` 串联证据。
- **降级方案：** MOCK 只允许彩排界面，不作为验收证据。
- **验收门槛：** 页面无 MOCK 标识、链路 ID 可追踪、四个 MVP 功能均输出且证据引用可回溯。

### P0-04 语音实机与故障回退

- **缺口：** 无 Chrome 正常、拒绝授权、断网、识别错误、TTS 失败五类记录。
- **主方案：** Chrome 桌面端逐类录屏，并记录首次响应和 10 秒回退。
- **备用方案：** Edge Chromium 复测浏览器兼容性。
- **降级方案：** 自动切换文字输入/文字播报，用户不丢失当前回答。
- **验收门槛：** 五类均可恢复；失败提示可见；任何语音失败不阻断面试。

### P0-05 官方链接与匿名访问

- **缺口：** 无当届入口、分享 URL、无痕/退出登录/异机/热点验证。
- **主方案：** 当届平台完成发布后按四种环境验证并截图。
- **备用方案：** 若匿名访问受平台限制，准备评委账号或现场二维码与权限说明。
- **降级方案：** 本地录屏仅作为故障备份，不能替代可访问提交链接。
- **验收门槛：** 至少两台设备可打开；核心演示无需编辑权限；链接与提交版本一致。

### P0-06 G8 用户验证

- **缺口：** 模板存在，但无 5–8 名真实用户数据。
- **主方案：** 按既定 10 项任务测试，收集完成率、用时、错误和访谈。
- **备用方案：** 时间不足时先做 5 人可用性测试，覆盖至少 2 类求职阶段。
- **降级方案：** 专家走查只用于发现问题，不计入用户验证样本。
- **验收门槛：** 核心任务完成率 ≥80%；P0 可用性问题清零；问题—修复—复测有闭环。

### P0-07 G9 提交包冻结

- **缺口：** PDF、MP4、简介、URL、Skill 导出和 10 次彩排证据未冻结。
- **主方案：** P0-01～P0-06 通过后生成哈希清单并冻结版本。
- **备用方案：** 平台临时故障时使用已验证录屏，同时保留现场互动入口。
- **降级方案：** 不删减四个 MVP；优先删去非核心动画和装饰内容。
- **验收门槛：** 10 次连续彩排成功；总时长符合赛制；所有材料指向同一提交版本。

## 三、P1/P2 项

### P1-01 Embedding 召回率验证

- 以 20 份脱敏简历 × 10 份 JD 建立人工标注集；验证召回率 ≥85%。
- 主方案为千帆 embedding；备用为规则+BM25；降级时必须降低置信度并解释关键词依据。

### P1-02 移动端与无障碍

- 至少 Chrome/Edge 与一台手机；验证键盘导航、焦点、对比度、字号、错误提示和语音替代路径。

### P2-01 中文分词/匹配优化

- 当前 unigram+bigram 是可控降级方案，不应在没有语料基线时直接换 jieba，否则既有阈值会漂移。
- 仅在标注集证明 Top-K 或召回率改善且不破坏阈值后，引入可选分词器。

### P2-02 模型盲测与用户研究

- 对候选模型执行统一样例、盲评表和成本/延迟记录；与 G8 同步收集用户信任、建议可执行性与面试压力数据。
