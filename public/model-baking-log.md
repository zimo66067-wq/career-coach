## 3. 对比维度

### 3.1 事实一致性

| 维度 | 定义 | 评分标准 |
|---|---|---|
| 事实锁合规 | 输出是否引入输入对象之外的专有名词/数字 | 通过 redflag.py = 0 分（无违规）；exit 1 = 不合格 |
| source_span 回指 | 评分理由引用的 source_span 是否可回指原文 | 100% 可回指 = 满分；<100% = 不合格 |
| JSON Schema 通过 | 输出是否通过 validate_schema.py | exit 0 = 通过；exit 1 = 不合格 |

### 3.2 结构通过率

| 维度 | 定义 | 评分标准 |
|---|---|---|
| Schema 通过率 | 多次输出中通过 validate_schema 的比例 | ≥90% = 合格；<90% = 不合格 |
| 字段完整率 | 必填字段非空的比例 | 100% = 满分 |
| 建议带证据率 | 修改建议中带 source_span 的比例 | 100% = 满分（验收门要求） |

### 3.3 延迟

| 维度 | 定义 | 门限 |
|---|---|---|
| 首响应延迟 | 从请求到第一个 token 返回 | F3 ≤8 秒 P95 |
| 总响应延迟 | 从请求到完整输出 | F1 ≤45 秒 P95；F2 ≤25 秒 P95；报告 ≤30 秒 P95 |
| 降级切换延迟 | 主模型超时到降级模型开始响应 | ≤10 秒 |

### 3.4 成本

| 维度 | 定义 | 备注 |
|---|---|---|
| Token 消耗 | 输入 + 输出 token 数 | 记录每次调用的 token 数 |
| 单次成本 | Token 数 × 模型单价 | 按模型定价计算 |
| 月度估算 | 按预估调用量计算月成本 | 假设 100 用户 × 每月 5 次完整使用 |

## 6. 盲测方法论

### 6.1 测试条件

- 同一输入文件、同一提示词、同一输出合同。
- 每个样例至少跑 3 次（检测输出稳定性）。
- temperature 统一设为 0.3（偏低，确保结构化输出稳定）。
- 记录每次的完整 JSON 输出、延迟、token 消耗。

### 6.2 复测规则

- 同一输入跑 3 次，3 次输出必须全部通过 Schema 校验。
- 3 次总分差 ≤5 分（PRD 验收门要求）。
- 如 3 次中有任一次不通过，记录失败原因并增加 2 次复测。

### 6.3 结果记录

- 每次盲测的完整输出保存到 `/tmp/model-baking/` 下（不入库）。
- 本文件只记录汇总结果与评分，不保存原始输出。
- 盲测日期与操作人必须记录。
